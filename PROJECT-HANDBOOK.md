## 1. What it is
A single-file web app (`app.html`) for a manager to assign maintenance/project tasks and technicians
to complete them, with a Gantt chart and a built-in "Ask" assistant.

- Multi-project **tasks + sub-tasks** (WBS 1, 1.1, 1.2…), collapsible.
- **6 dates** per task: Baseline / Planned / Actual — each Start + End.
- Priority, status (Not Started / In Progress / Completed / On Hold / Blocked), % complete.
- **Gantt chart:** baseline + planned + actual bars, "today" line, Day/Week/Month scale,
  wrapped labels, **Export PNG** and **Print**.
- **Cloud sync:** shared team database — everyone signed in sees the same live data.
- **Ask assistant:** ask questions and get answers pulled from all your tasks (see §4).

## 2. Roles (who can do what)
- **Manager** (the first person who signs up becomes manager automatically):
  create/assign tasks, set plan dates, attach an **instruction photo**, manage projects, and open
  **Team** to set everyone's role. Sees the full tool + Gantt.
- **Technician:** sees all tasks (read-only) with a **"My tasks only"** filter; can complete only the
  tasks assigned to them — set status/%/actual dates, **items taken from the tool crib for
  replacement**, **date closed**, **reason if still in progress**, completion remarks, and a
  **completion photo**.
- New sign-ups start **Unassigned** until the manager gives them a role (nobody can self-promote).

## 3. How to use
1. Open https://RJA9291.github.io/ProjectManagement/ (or Add to Home Screen on iPhone via Safari →
   Share → Add to Home Screen for an app icon + offline use).
2. Sign in with **email + password** (☁ button / the sign-in screen).
3. **Manager:** click **Add Task** → fill name, assign to a technician, dates, priority, instructions,
   optional instruction photo. Use **Team** (people icon) to set roles for new members.
4. **Technician:** open a task assigned to you → fill the **Completion** section + completion photo.
5. **Gantt** tab → **Export PNG** or **Print** for reports.

## 4. The "Ask" assistant
Click **Ask** (top bar). It reads **all** projects/tasks in the app and answers, e.g.:
- `ringkasan` / `summary` — totals by status, overall %, overdue list.
- a person's name (e.g. `tugas Ali`) — that person's tasks.
- a status: `lewat`/`overdue`, `sedang`/`in progress`, `siap`/`completed`, `belum`/`not started`, `tersekat`/`blocked`.
- a keyword from a task name (e.g. `RFI`) — matching tasks, or full detail if one matches.

It is a **local** assistant (runs in the app, no external AI) — private, free, works offline. It does
not do open-ended AI chat; that would need an API key.

## 5. Setup that was done (Supabase)
- SQL run in Supabase → SQL Editor: `supabase-roles.sql` (tables `profiles`, `projects`, `tasks` +
  row-level security + triggers + private `task-photos` Storage bucket). Earlier: `supabase-setup.sql`.
- **Auth → Providers → Email:** "Confirm email" turned **OFF** (instant signup).
- **Auth → URL Configuration:** Site URL set to the Pages URL (so magic-link / password-recovery
  emails point to the real app, not `localhost:3000`).
- The app embeds only the Supabase **URL + publishable key** (safe). The database password /
  service-role key are secret and are NOT in the app or repo.

## 6. Security notes
- Keep the Supabase **DB password / service-role key** private — never paste them into the app, repo,
  or chat.
- The repo is **public** (needed for free GitHub Pages) — don't store confidential data in task text.
- Commit emails were scrubbed to a GitHub noreply address.

## 7. How to update the app (for a developer / Claude)
- Edit `app.html` (the single source of truth). Never hand-edit `index.html` — it is generated by
  `.claude/build-pages.sh`.
- Re-publish the Artifact, then `git add -A && git commit && git push`. GitHub Pages redeploys in
  ~1–2 minutes. Bump `VERSION` (in app.html) and `CACHE` (in sw.js) each release.
- Full technical notes are in the **`task-tracker` skill** (`~/.claude/skills/task-tracker/SKILL.md`).
